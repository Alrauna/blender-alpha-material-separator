# Release 1.0 Transition Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Promote the extension to `1.0.0`, validate its installable archive,
fast-forward the completed feature history into local `main`, and create the
vendor-neutral `ci/automation` branch.

**Architecture:** Keep the manifest and runtime capability payload as the two
release-version authorities and add one unit contract proving they agree.
Update only current user/process documentation, preserve historical
Superpowers artifacts, then use Git's native `--ff-only` guard for integration.

**Tech Stack:** Python 3.13 `unittest` and `tomllib`, Blender 5.2 extension
commands, PowerShell, Git.

## Global Constraints

- Extension version becomes `1.0.0`; public integration API remains `1.2`.
- Do not change runtime behavior, operators, classifications, policies, or
  payload structure.
- Preserve historical Superpowers specifications and plans that record
  `0.1.0`.
- Build output remains ignored under `.packaged-releases/`.
- Do not fetch, pull, push, force, rewrite history, delete branches, or alter
  remotes.
- Retain `feat/alpha-material-separator-0.1` as a local recovery reference.
- Do not add `.github/workflows/` or implement CI in this plan.
