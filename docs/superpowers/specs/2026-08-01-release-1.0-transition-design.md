# Release 1.0 Transition Design

## Goal

Promote Blender Alpha Material Separator from extension version `0.1.0` to
`1.0.0`, validate the resulting installable ZIP, fast-forward the completed
feature history into local `main`, and create `ci/automation` for the
separately designed CI milestone.

## Scope

The transition changes release identity only. It does not change analysis,
classification, resolver, cache, preview, assignment, UI, public operators, or
the versioned integration API. The public API remains `1.2`.

Current release authorities and instructions move to `1.0.0`:

- `addon/blender_manifest.toml`
- `addon/api_contract.py`
- `tests/unit/test_api_contract.py`
- `README.md`
- `docs/integration-api.md`
- `docs/material-support.md`
- `docs/testing.md`
- `PLAN.md`
- `AGENTS.md`
- `docs/HANDOFF.md`

Historical Superpowers specifications and implementation plans retain their
original `0.1.0` constraints. They document decisions at the time and are not
current release authorities.

## Version consistency

The existing API contract test changes first and must fail while runtime still
reports `0.1.0`. It then verifies:

- the manifest version is `1.0.0`;
- the runtime capability payload reports `1.0.0`;
- those values are equal;
- the public API remains `1.2`.

The implementation changes only the manifest version and
`api_contract.EXTENSION_VERSION`. User-facing installation instructions and
current support headings then follow the same release identity.

The README no longer describes release validation as unfinished. Package
instructions use `alpha_material_separator-1.0.0.zip`.

## Verification and package

Run:

1. The focused API contract test in RED and GREEN states.
2. All 51 ordinary Python tests.
3. The complete headless Blender suite.
4. Source extension validation.
5. Extension build.
6. Validation of
   `.packaged-releases/alpha_material_separator-1.0.0.zip`.
7. `git diff --check`.

The built archive remains ignored and is not committed.

## Commit and branch transition

Commit the verified version transition on
`feat/alpha-material-separator-0.1` as:

```text
chore: release version 1.0.0
```

Then:

1. Switch to local `main`.
2. Fast-forward with
   `git merge --ff-only feat/alpha-material-separator-0.1`.
3. Run the unit, headless Blender, and source-validation gate again on `main`.
4. Retain the feature branch as a recoverable local reference.
5. Create and switch to `ci/automation` from the verified local `main`.

Do not fetch, pull, push, force, rewrite history, delete branches, or alter the
remote.

## GitHub Actions boundary

Creating `ci/automation` does not authorize workflow implementation.
No `.github/workflows/` files, Actions dependencies, marketplace actions, or
remote operations are added during this transition. GitHub Actions receives a
separate design and test-first implementation plan.

## Success criteria

- Manifest, runtime capability payload, README, current documentation, and
  package filename consistently report `1.0.0`.
- Public API remains `1.2`.
- All required tests and validations pass before and after the fast-forward.
- Local `main` contains the complete feature history without a merge commit or
  rewritten commit.
- The final checked-out branch is `ci/automation`.
- The remote remains unchanged and nothing is pushed.
